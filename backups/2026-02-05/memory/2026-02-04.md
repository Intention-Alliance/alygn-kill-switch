### Key Findings

#### Root Cause: Double Token Budget Enforcement
The RAG pipeline enforces token budgets 3 times, causing aggressive filtering:
1. `retrieveAssistantAnswerMemories()` - defaults to 600 tokens
2. `buildSimpleRagPromptBlocks()` - enforces 1500 tokens
3. Results trimmed at 600 never make it through

**Fix:** Pass `tokenBudget: 1500` to the retrieval call.

#### Secondary Issue: Aggressive Cosine Threshold
- Current: `minCosine: 0.7` (very strict)
- Default in retrieval: `0.6` (more reasonable)
- Many relevant memories (0.6-0.7 range) filtered out

**Fix:** Lower to `0.6`.

#### Tertiary Issue: Silent Failures
- No debug logging when blocks are empty
- Makes debugging impossible

**Fix:** Add comprehensive logging to trace filtering pipeline.

## Technical Notes

### RAG Architecture (Masterbots)
```
User Query
  ↓
getRagContext()
  ↓
retrieveAssistantAnswerMemories()
  ├→ embedText1536(query) → OpenAI API
  ├→ runSearch() → PostgreSQL (cosine similarity)
  ├→ enforceTokenBudget() → Filter by tokens (600 default)
  └→ Return memories[]
  ↓
buildSimpleRagPromptBlocks()
  ├→ Filter by minCosine (0.7)
  ├→ Deduplicate vs last assistant
  ├→ enforceTokenBudget() (1500 tokens)
  └→ Format into prompt blocks
  ↓
Inject into finalUserPrompt
  ↓
Send to AI model
```

### Critical Bugs Root Causes Identified

#### 🔴 Issue #578 Bug 3: H3+ Sections Breaking
**Root Cause Found:** `handleDocumentUpdate()` line ~490
- When replacing a section, `contentEnd` only includes direct content
- Does NOT include child sections (H3, H4, etc.)
- Children get orphaned or duplicated when parent section updated

**The Fix:**
```typescript
// Current (WRONG):
absoluteEnd = sectionContentEnd  // Stops at first child

// Should be:
const nextSiblingIndex = sections.findIndex((s, i) => 
  i > sectionIndex && s.level <= currentSection.level
)
absoluteEnd = nextSiblingIndex !== -1 
  ? sections[nextSiblingIndex].headingStart 
  : currentContent.length
```

#### 🟡 Issue #578 Bug 1: Document Not Updating After Creation
**Root Cause:** Race condition in `use-workspace.tsx` line ~425
- `addDocument()` starts async mutation
- Navigation happens immediately (sync)
- Document loads from stale cache before mutation completes

**Fix:** Use `mutateAsync()` + await before navigation

#### 🟡 Issue #578 Bug 4: Version List Not Refreshing
**Root Cause:** Version query cache not invalidated after save
**Fix:** Explicit `queryClient.invalidateQueries(['versions', ...])`

#### 🔴 Issue #578 Bug 2: 15% Mobile Idle Rate
**Root Cause:** No SSE resilience in `use-mb-chat.tsx`
- No retry logic in Vercel AI SDK's useChat config
- No timeout detection
- No visibility change handling (mobile Safari sleep)
- `onError` handler only logs, doesn't retry

**Fix:** Custom fetch with retry + exponential backoff + timeout

#### 🟡 Issue #555: Markdown Parsing Performance
**Root Cause:** `parseMarkdownSections()` called on EVERY streaming chunk
- Line ~372 in `use-workspace-chat.tsx`
- For 10MB documents, causes UI lag

**Fix:** Cache parsed sections during streaming operation
