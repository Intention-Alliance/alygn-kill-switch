## 🔧 Critical Learnings

### 1. Arch Linux Nginx Pattern
- **Does NOT use** `sites-enabled/` directory (unlike Debian/Ubuntu)
- **Uses monolithic** `/etc/nginx/nginx.conf`
- Symlinks in `sites-enabled/` are **never loaded** unless explicitly included
- **Solution:** Replace entire `/etc/nginx/nginx.conf` with custom config

### 2. Vite Base Path Mismatch
- Vite config had `base: '/'` but nginx was configured for `/admin/`
- HTML referenced `/assets/file.js` but nginx expected `/admin/assets/file.js`
- **Result:** 404s on all assets, MIME type errors
- **Solution:** Match nginx root to Vite build output:
  ```nginx
  location / {
      root /var/www/admin;  # Not /var/www
      try_files $uri $uri/ /index.html;  # SPA routing at root
  }
  ```

### 3. Docker COPY Path Structure
- Service imports: `import from '../redis/redis-pool.mjs'`
- Dockerfile must copy to matching paths:
  ```dockerfile
  COPY redis/redis-pool.mjs ./redis/redis-pool.mjs      # ← Matches import
  COPY tracing/tracing-sdk.mjs ./tracing/tracing-sdk.mjs # ← Matches import
  ```
- Build context: `..` (phase0 directory)
- **Lesson:** COPY paths must match runtime import paths exactly

### 4. SSL Key Permissions
- Nginx on Arch runs as user `http`
- SSL key must be readable by nginx worker:
  ```bash
  sudo chown root:http /etc/ssl/private/andlersrv.tail62d797.ts.net.key
  sudo chmod 640 /etc/ssl/private/andlersrv.tail62d797.ts.net.key
  ```
- **Symptom:** nginx -t fails, reload aborts, new config never loads

### 5. try_files Catching Assets
- Wrong: `try_files $uri $uri/ /admin/index.html` catching asset requests
- Assets returned HTML instead of CSS/JS (MIME type errors)
- **Solution:** Separate location block for assets BEFORE SPA fallback:
  ```nginx
  location ~* \.(js|css|png|jpg|jpeg|gif|ico|svg|woff|woff2|ttf|eot)$ {
      root /var/www/admin;
      expires 1y;
      add_header Cache-Control "public, immutable";
  }
  
  location / {
      root /var/www/admin;
      try_files $uri $uri/ /index.html;
  ```

## 🧠 Redis Cluster Initialization Issue

**Problem:** "CLUSTER DOWN Hash slot not served" error after deployment

**Root Cause:** The `redis-cluster-init` container command was malformed:
```yaml
# WRONG - shell escaping broke the command
command: >
  sh -c "redis-cli --cluster create redis-node-1:6379 ..."
```

**Fix:** Manually initialized cluster:
```bash
docker exec redis-node-1 redis-cli --cluster create \
  redis-node-1:6379 redis-node-2:6379 redis-node-3:6379 \
  --cluster-replicas 0 --cluster-yes
```

**Lesson:** Redis cluster nodes don't auto-join - explicit initialization required. Use array syntax in docker-compose for complex commands.

**Current Status:** ✅ Cluster initialized, all 16384 slots covered
