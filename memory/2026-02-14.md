## Critical Correction: Sub-Agent Pattern

### The Problem (Feb 13)

Tried to use `sessions_spawn` from a Node.js script:

```javascript
// WRONG - Scripts don't have tool access!
const { stdout } = await execAsync(
  `openclaw sessions spawn --task="..." --timeout-seconds=180`
);
```

Result: 10 VCs "researched" but all empty (0/10 ready for outreach)

### Root Cause

- `sessions_spawn` is a **tool only AI agents can use**
- Scripts can't call OpenClaw tools directly
- Shell `exec` can't trigger tool execution in agent session
- Sub-agents returned generic text, not structured JSON

### The Fix (Feb 14)

Read official docs: https://docs.openclaw.ai/tools/subagents

**Correct architecture:**

```
Script → Posts Discord → Wobblus sees request → Uses sessions_spawn
  ↓
Wobblus spawns sub-agents → Execute web_search/web_fetch → Return JSON
  ↓
Wobblus saves to /tmp/vc-research-[name]-result.json
  ↓
Script waits for file → Reads JSON → Updates Notion
```

**Key principle:** Scripts orchestrate. AI executes tools. Files coordinate.

## Implementation: `deep-research-vcs-v3.js`

**Purpose:** One-by-one VC research with proper sub-agent pattern

**How it works:**

1. Load 1 VC from Notion
2. Check if researched (cache in /tmp/)
3. If not cached:
   - Post request to Discord #annotations
   - Wait 30s for results file
   - If timeout, skip to next
4. If results exist:
   - Read structured JSON
   - Update Notion (emails, pain points, thesis, governance)
   - Mark "Ready for outreach"
5. Next iteration when script runs again

**Usage:**
```bash
node deep-research-vcs-v3.js --limit=1          # One VC
node deep-research-vcs-v3.js --limit=5          # Five VCs
node deep-research-vcs-v3.js --vc-name="Lux"    # Specific VC
node deep-research-vcs-v3.js --dry-run          # Preview only
```
