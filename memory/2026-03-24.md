# Memory Log - 2026-03-24

## Critical Learnings: VC Outreach Filtering

### Problem Discovered
The alygn-outreach skill was not properly filtering out VCs that had already been sent, causing duplicate email sends.

### Root Causes Found by Team

**1. Missing `await` on async filter function (CRITICAL)**
- Location: Pipeline.js lines 391 and 482
- Issue: `filterAlreadySent()` returns a Promise but was called without `await`
- Impact: All VCs passed through filtering, duplicates sent

**2. Wrong Notion API endpoint**
- Location: notion-client.js
- Issue: Using `dataSources.query` instead of `databases.query`
- Impact: Notion queries silently failed, couldn't check Status = "Sent"

**3. Silent error handling**
- Location: Pipeline.js `wasAlreadySent()`
- Issue: Empty catch block `catch (e) { }` swallowed all errors
- Impact: When Notion failed, function returned false (not sent), duplicates sent

### Fixes Applied
- ✅ Added `await` to `filterAlreadySent()` calls
- ✅ Changed Notion API to `databases.query`
- ✅ Added error logging instead of silent failures
- ✅ Added intermediate filters in `runPersonalize()` stage

### Key Insight
The TWO-LAYER check design is correct but was broken by implementation bugs:
1. sent-emails.json - fast local check for system sends
2. Notion Status = "Sent" - authoritative check for ALL sends (manual + system)

When Notion check failed silently, the filter defaulted to "not sent" - wrong fail-safe.

### Draft ID Naming Convention (CRITICAL)
**Lesson:** Draft filenames must use `nanoid(6)` format, NOT descriptive names.

**Correct pattern:** `draft-vc-[nanoid(6)].json`
- ✅ Example: `draft-vc-wSLW0q.json` 
- ✅ Example: `draft-vc-8mrB1M.json`
- ❌ Wrong: `draft-index-ventures-neil.json`
- ❌ Wrong: `draft-a16z-marc.json`

**Why nanoid(6):**
- Easier to identify and track
- Less tokens in prompts
- Consistent with existing workflow
- Prevents naming collisions
