## 🔧 Key Lessons Learned (Apr 23)

### Zero-Trust Verification Protocol

**What Worked:**
- ✅ Cross-referenced audit findings with GitHub issues
- ✅ Verified Supabase tables via direct JS client test
- ✅ Tested dry-run pipelines before production
- ✅ E2E tests validate remote DB sync

**What to Maintain:**
- Always verify with external systems (Supabase, Notion, IMAP) before trusting internal logs
- Cross-reference multiple sources (logs + remote DB + external verification)
- Throw errors on sync failure (don't silently continue)
- Quality gates before marking "Approved" or "Ready"

### Personalization Quality Gates

**Before (Broken):**
- ❌ Generic pain points ("AI safety standards", "gobernanza de IA")
- ❌ Empty `typeData` (no portfolio, partners, population)
- ❌ Wrong greetings ("Estimado/a Tania" for all municipalities)
- ❌ Placeholder data ("50,000 habitantes" — fake number)

**After (Fixed):**
- ✅ Pain points from Supabase (`municipalities.pain_points`, `vc_research.pain_points`)
- ✅ Portfolio/partners from Perplexity API → stored in `vc_research`
- ✅ Greetings from `typeData.decisionMakers` (actual alcalde names)
- ✅ Real demographics (population, province from Supabase)

**Quality Gate Rules:**
1. Enrichment must happen BEFORE personalization
2. typeData must be validated before marking "Approved"
3. Greeting must use actual contact names from research
4. Never use wrong contact name (Tania is not universal)

### Architecture Pattern: Script ↔ AI Execution

**Correct Pattern (from VC outreach pipeline):**

```
Script: Coordinates workflow, loads/saves files, updates external systems
  ↓
Wobblus (AI): Executes tools (web_search, web_fetch, analysis)
  ↓
File: Caches results (/tmp/[name]-result.json)
  ↓
Script: Reads cache, updates Notion/Discord
```

**Why This Works:**
- Tools need session context (auth, LLM) that scripts don't have
- Scripts are orchestrators, AI agents are executors
- File caching avoids re-execution (efficiency)
- Separation of concerns = clean architecture

**Anti-Patterns to Avoid:**
- ❌ Scripts trying to call `openclaw run` or `openclaw sessions spawn` with inline tasks
- ❌ Scripts attempting to call built-in tools directly
- ❌ Creating new scripts when fixing existing ones would work
- ❌ Simulating work (placeholder workflows) instead of executing
