**Response:** `{"error":{"code":"UNAUTHORIZED","message":"Missing X-Webhook-Key or Authorization header"}}` — HTTP 401

**Root cause:**
1. The running openclaw-webhook process (PID 1230123) does NOT have `KILL_SWITCH_INTERNAL_KEY` env var set
2. Without the internal key, `verifyApiKeyViaDbLookup()` returns `{ ok: false, error: 'missing-internal-key' }` immediately
3. The code falls through to the env-var fallback (`WEBHOOK_API_KEY`), which is set to the old bootstrap key `wk_kvlGrfkWJIinquVRyeCgrXsOTxBpEctVQNWwwAAYVxM`
4. The new key doesn't match the env-var key, so auth fails

**Verification:** The old bootstrap key DOES pass auth (returns HTTP 502 from Ollama — "model is required"), confirming the env-var fallback path works correctly. The issue is specifically that the DB lookup path is non-functional because the env var isn't configured.

**Code assessment:** The code is correct. The `verifyApiKeyViaDbLookup()` function in `server.ts` lines 123–195 properly:
- Checks for `KILL_SWITCH_INTERNAL_KEY`
- Fetches from `${KILL_SWITCH_API_URL}/v1/internal/api-keys/lookup?prefix=...`
- Compares sha256 hash with `timingSafeEqual`
- Checks revocation and expiry
- Checks scope membership

This is a **deployment configuration issue**, not a code bug. To fix:
1. Generate `KILL_SWITCH_INTERNAL_KEY` (`openssl rand -hex 32`)
2. Set it in both the kill-switch container env and the openclaw-webhook process env
3. Rebuild the kill-switch container with the PR #41 code so the internal endpoint is available
4. Restart both services
